# Docs Studio

이 저장소의 마크다운을 **읽고, 그 자리에서 AI에게 고치게 하는** 로컬 전용 웹 앱.

- 문서 244편을 렌더링해서 본다. SVG 961장은 인라인으로 들어가고 내부 링크는 앱 안에서 이동한다.
- **그림을 클릭**하면 재생성 패널이 열린다. 지시를 적으면 모델이 SVG를 다시 그린다.
- **본문을 드래그**하면 Copilot의 inline chat 같은 입력창이 떠오른다. 그 구간만 고쳐 쓴다.

AI 결과는 **곧바로 파일에 쓴다.** 대신 모든 편집을 백업하고 저널에 남겨서, 앱을 재시작해도
되돌릴 수 있다. 쓰기 전에는 SVG 규격과 마크다운 무결성을 검사해 통과하지 못하면 쓰지 않는다.

---

## 시작하기

```bash
cd tools/docs-studio
npm install

cp .env.example .env      # 키와 baseUrl 을 채운다
npm run dev               # API(5174) + Vite(5173) 를 함께 띄운다
```

→ http://localhost:5173

빌드해서 한 프로세스로 돌리려면:

```bash
npm run build
npm start                 # http://localhost:5174
```

`.env` 없이도 뜬다. 그때는 읽기 전용 뷰어로 동작한다.

### 환경 변수

| 변수 | 뜻 | 기본값 |
|------|-----|--------|
| `OPENAI_API_KEY` | API 키. 서버에만 있고 브라우저로 내려가지 않는다 | (없음) |
| `OPENAI_BASE_URL` | OpenAI 호환 엔드포인트. `/v1` 까지 포함 | `https://api.openai.com/v1` |
| `OPENAI_MODEL` | 본문 편집에 쓸 모델 | `gpt-4o` |
| `OPENAI_MODEL_SVG` | 그림 재생성용 모델. 비우면 `OPENAI_MODEL` | (없음) |
| `OPENAI_TIMEOUT_MS` | 요청 타임아웃 | `180000` |
| `PORT` | API 서버 포트 | `5174` |
| `REPO_ROOT` | 대상 저장소. 보통 건드릴 일이 없다 | 이 앱의 두 단계 위 |

`OPENAI_BASE_URL` 만 바꾸면 vLLM·Ollama·사내 프록시에 그대로 붙는다.
`POST {baseUrl}/chat/completions` 하나만 쓰고 SDK 의존성이 없다.

## 쓰는 법

| 하고 싶은 것 | 방법 |
|---|---|
| 그림 다시 그리기 | 그림을 클릭 → 지시 입력 → `Ctrl+Enter` |
| 본문 구간 고치기 | 본문을 드래그 → 떠오른 입력창에 지시 → `Ctrl+Enter` |
| 선택 후 입력창 다시 띄우기 | `Ctrl+I` |
| 되돌리기 | 알림의 `되돌리기`, 또는 상단 `이력` 패널 |
| 학습 진도 체크 | 체크리스트의 네모를 클릭 (이 브라우저에만 저장된다) |
| 문서 찾기 | 왼쪽 검색창 (2글자 이상) |
| 테마 | 상단 오른쪽 ☀/☾ |

드래그 편집은 **블록 단위로 스냅**된다. 문장 일부를 드래그해도 그 문단 전체가 대상이 되고,
드래그한 부분은 "여기에 초점을 맞춰라"로 모델에 따로 전달된다. 무엇이 바뀔지는 실행 전에
화면에 하이라이트로 표시된다.

**다이어그램 앵커(`<!-- diagram:… -->`), 이미지 줄, 보존된 원본 ASCII 주석은 편집할 수 없다.**
드래그해도 입력창이 뜨지 않는다. 그림은 클릭해서 고친다.

### 학습 진도 체크리스트

`- [ ]` / `- [x]` 는 진짜 체크박스로 렌더된다. 저장소 README 들이 학습 진도를 이 문법으로
관리하기 때문이다.

**체크는 md 파일에 쓰지 않는다.** 개인의 진도라 이 브라우저의 `localStorage` 에만 남는다
(`docs-studio-tasks:<문서경로>`). 파일이 바뀌지 않으므로 git diff 에도 잡히지 않고,
다른 사람의 진도와 충돌하지도 않는다.

열쇠는 줄 번호가 아니라 **항목 글자의 해시 + 문서 안 등장 순서**다. 문서를 편집해 줄이
밀려도 체크가 엉뚱한 항목으로 옮겨가지 않는다. 코드 펜스 안의 `- [ ]` 는 예시일 뿐이라
체크박스로 바꾸지 않는다.

## 안전장치

편집이 파일에 닿기까지 네 겹을 지난다.

1. **낙관적 잠금** — 문서를 연 시점의 해시와 디스크가 다르면 쓰지 않는다.
2. **검증** — 통과하지 못하면 쓰지 않는다.
   - SVG: XML 파싱, 루트 `<svg>`, `viewBox="0 0 880 H"`, 한글 폰트 폴백,
     `<title>`/`<desc>`, 전면 흰 배경, 금지 태그(`script`·`foreignObject`·`style`·`image`·`a`·`animate*`),
     `on*` 속성·`javascript:`·외부 URL, 캔버스 이탈 좌표
   - 마크다운: 코드 펜스 짝, **HTML 주석 짝**, 다이어그램 앵커 불변,
     새 링크의 실존 여부, 편집 구간 뒤쪽 블록 구조 불변
   - SVG가 걸리면 오류를 모델에 돌려주고 **한 번만** 다시 시킨다.
3. **백업 + 저널** — `.history/blobs/` 에 변경 전 전문을, `journal.jsonl` 에 기록을 남긴다.
   순서는 blob → 저널(fsync) → 원자적 rename. 중간에 죽어도 "기록은 있고 파일은 그대로"인
   안전한 쪽으로만 깨진다.
4. **원자적 쓰기** — 임시 파일에 쓰고 `fs.rename`. 반쪽짜리 파일이 남지 않는다.

그 위에 git 이 있다. **작업 전에 커밋해 두는 것을 전제로 한다.**

### 줄바꿈

이 저장소는 마크다운 244개, SVG 961개가 전부 CRLF다 (`core.autocrlf=true`).
파싱과 줄 번호 계산은 LF로 정규화한 문자열 위에서만 하고, 디스크로 돌아갈 때 원래 형식으로
되돌린다 (`server/eol.js`). 이걸 건너뛰면 파일 전체가 "수정됨"으로 뜨거나 splice가 줄을 어긋나게 자른다.

## 검사

```bash
npm run check            # 244개 문서 전수 렌더 검사
```

문서 개수, 다이어그램 961개, 인라인된 SVG, ASCII 보존 주석 912개, 내부 링크 유효성,
줄 범위 정합성을 한꺼번에 본다. 원본 ASCII가 본문으로 새는지도 여기서 잡는다.

쓰기 경로까지 태우려면 목 AI 서버를 쓴다. 실제 키가 필요 없다.

```bash
node scripts/mock-ai.js &
OPENAI_API_KEY=dummy OPENAI_BASE_URL=http://127.0.0.1:5199/v1 npm start &
node scripts/e2e.js
```

스트리밍, 검증 실패 후 재시도, 되돌리기, 보호 구역 거부, 낙관적 잠금, 업스트림 오류 전달을
확인한다. 실제 파일을 고쳤다가 되돌리므로 **끝나면 `git status` 가 깨끗해야 한다.**

목 서버는 지시문에 넣은 표식으로 시나리오를 고른다 — `MOCK:bad-svg`, `MOCK:slow`, `MOCK:error`.

## 구조

```
server/
  config.js    경로 해석과 저장소 경계 (루트 밖으로 못 나간다)
  eol.js       CRLF ↔ LF 정규화
  docs.js      트리, 읽기, 원자적 쓰기, 줄 splice, 검색
  diagram.js   다이어그램 삽입 블록 파서 (마커 / 이미지 / ASCII 주석)
  render.js    markdown-it — 줄 범위 주입, SVG 인라인, 링크 재작성
  svgtool.js   인라인 시 id 충돌 제거
  validate.js  SVG·마크다운 검증, 모델 응답에서 결과물 추출
  history.js   백업, 저널, 되돌리기, 경로별 잠금
  ai.js        프롬프트와 OpenAI 호환 스트리밍 클라이언트
  index.js     HTTP + SSE

web/src/
  selection.ts  선택 영역 → 원문 줄 범위 (블록 스냅)
  App.tsx       라우팅, 선택·클릭 처리, 알림
  InlineChat.tsx / DiagramPanel.tsx / Sidebar.tsx / HistoryPanel.tsx
```

렌더 시 모든 블록 토큰에 `data-src-start` / `data-src-end` 를 심는다.
브라우저 `Range` 에서 가장 가까운 그 속성을 가진 요소를 찾아 줄 범위를 얻고, 줄 단위로
splice 한다. 문자 오프셋을 되짚지 않으므로 원문이 어긋날 수가 없다.

## 알려진 한계

- **되돌리기는 파일 전체를 되쓴다.** 같은 파일을 여러 번 고쳤다면 최신 것부터 차례로 되돌려야 한다.
- **검증은 구조만 본다.** 글자 겹침·어색한 배치 같은 시각적 품질은 걸러내지 못한다.
  패널의 before/after 비교와 되돌리기가 실질적 방어선이다.
- 그림 일괄 재생성 기능은 **의도적으로 만들지 않았다.** 961장을 한꺼번에 바꾸면 검토가 불가능하다.
